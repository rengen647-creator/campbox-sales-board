# Sales → CSM: приёмка перед релизом (14.10.2026)

**Статус:** код и SQL находятся в отдельной ветке. Миграция не применена к рабочему Supabase. Production GitHub Pages не обновлялись.

## Проверенные статические сценарии
- [x] `normalizeContract` сохраняет ID, `signed_date` и статус.
- [x] При изменении на «Подписан» пользователь должен указать фактическую дату.
- [x] Сейлз показывает «КСМ: в очереди назначения» / «КСМ: назначен» / «Нужна сверка» из таблицы статусов с включённым RLS.
- [x] Сохранение возвращает сигнал успеха или ошибки.
- [x] Серверный обработчик явно допускает только `daily_reflection` с `status=signed` (NULL-safe comparison).
- [x] Создание `salary_contracts` отсутствует в миграции подписания.
- [x] Менеджер может оформить новый договорный цикл существующего клиента из общей базы, не создавая дубль.
- [x] JavaScript модули синтаксически корректны.

## Обязательные интеграционные сценарии в изолированном Supabase
- [ ] Два события «На подписании» и «Не состоялся»: число CSM-клиентов не изменилось.
- [ ] «Подписан» + дата: одна запись в `salary_clients`, одна в `csm_camps`, связаны через `sales_client_id`.
- [ ] Повторное сохранение дня, смена планов/комментариев: дублей нет.
- [ ] Два менеджера одновременно подписывают один и тот же лагерь: блокировка исключает дубли.
- [ ] Повторный договор после расторжения: CSM ID, история фич и контактов сохранены; `salary_contracts` без подтверждения руководителя не пополнилась.
- [ ] Одно название соответствует нескольким клиентам: статус «conflict», ложное объединение запрещено.
- [ ] Два различающихся названия, похожие после нормализации: ручная сверка, если неоднозначно.
- [ ] Смена статуса подписания на ошибочный: историю не удаляем; требуется отдельное исправление руководителем.
- [ ] Менеджер Sales не читает чужие записи через `sales_handoff_status`; анонимный запрос отвергается.
- [ ] Сотрудник CSM видит только назначенные ему лагеря; руководитель видит неназначенных.
- [ ] Смена имени, пауза и расторжение не стирают историю и не вмешиваются в начисления.
- [ ] Работает создание зарплатного договора для уже переданного лагеря.
- [ ] Бэкап/откат и проверка конфликтов `campbox_internal.csm_sales_sync_conflicts`.
- [ ] Приёмка CSM-очереди из PR #4, затем публикация в согласованном порядке.
