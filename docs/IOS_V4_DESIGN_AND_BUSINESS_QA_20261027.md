## Почему предыдущая V3 не прошла визуальную приёмку
На предоставленном пользователем снимке пять элементов «Мой план сегодня» видны как обрезанные горизонтальные полосы, подписи и поля частично скрыты. При этом большинство страниц по-прежнему воспроизводили прежнюю композицию. Следовательно, проверки JavaScript без реального браузера были недостаточны. **Никаких утверждений о полном визуальном QA V3 больше не делаем.**

## Реальные изменения V4
- В `ui-v13.js` заменено содержимое `renderToday`: пять канонических метрик теперь показываются отдельными независимыми блоками `ios4-activity`, а не прежними табличными/плоскими блоками.
- На широком экране блоки расположены в адаптивной сетке 2×2+1 (при меньшей ширине по одному). У каждой карточки есть иконка, читаемое название, цель, единственное поле факта, прогресс, раскрываемое обоснование.
- Кольцевой индикатор выполнения дня даёт основную иерархию и исключает конкурирующие процентные подписи.
- `ios-v4.css` задаёт отдельную систему визуальных токенов, плотность, границы, источники цвета для светлой и тёмной тем, hero-свод и другой вид основных модулей.
- `ios-v4.js` добавляет контекстные визуальные символы к страницам, сохраняя исходные рендереры и маршруты.
- Сигналы «Что требует внимания» остаются в нормальном потоке DOM и имеют раскрываемый текст из ранее вычисленных данных.
- Финансы, команда, зарплата, контракты, отчёты используют унифицированные поверхности, вкладки, иерархию, контекстные заголовки; настоящие фильтры и таблицы не подменяются макетными.
- Поля ввода, статусы, кнопки и данные имеют единственный источник истины; нет дублей форм, запускающих повторную запись в базу.

## Бизнес-приёмка
| Проверка | Источник | Должно оставаться верным |
|---|---|---|
| План дня | `coachAutoPlan`, `daily_sales` | По каждому из пяти показателей вводится один факт; `changed()` вызывает автосохранение, `recalc()` обновляет графики |
| Продажи | `daily_sales`, `month_settings` | Цель, факт и воронка не пересчитываются в CSS или дополнительном JS |
| Контрактинг | `activeContractEntries`, `openContracts` | Договоры открываются и сохраняются прежними обработчиками, комментарии и дата контакта не теряются |
| Финансы | `sales_finance_charges`, `salary_payments` | Начислено, поступило и накопительный итог не смешиваются; фильтры работают |
| Команда | `coachForecastData`, `profiles` | Сотрудник не видит чужие данные, менеджер получает доступ по своим реальным ролям и RLS |
| Удержание | `salary_retentions` | Успех добавляет только существующее 6-месячное окно, без дубля стандартного периода |
| Зарплата | `salary-v1.js` | Статусы выплат и формулы остаются неизменными |
| Sales→CSM | `sales_handoff_statuses` | Подписанный договор не создаёт повторную передачу |

## QA gate
- Node: original calculation suites, salary retention cases, payment tabs, signed handoff, actual `renderToday` event-path integration.
- Real Chromium with synthetic inputs: widths 375 / 430 / 820 / 980 / 1280 / 1593px, both light/dark; at least 145px height per card; 5 distinct input fields; no overlap or horizontal overflow; full explanation expands card.
- Screenshots persisted as CI artifacts for comparison. **This is synthetic browser QA, not test of an authenticated user session.**
- If any test fails, **do not merge**.
- Manual acceptance after merge: users in both roles, actual data and events, Tilda iframe, old browser cache, input focus and Save.

## Не закрытые бизнес-риски
- P0: база процентного выполнения отдела для ставки контракторства (`min_plan` vs `target_plan`) требует отдельного бизнес-решения; формулы не меняются.
- P1: предварительные платежи в зарплатном суммировании, первичная фиксация исторического месяца, пагинация зарплатных поступлений — не изменены данным редизайном.
- Основной реестр рисков: `qa/SALES_BOARD_BUSINESS_QA_20261027.md`.
